# Agent instructions

Read [README](README.md), [database guide](database/README.md), [admin contract](docs/admin-data-contract.md) and [notification architecture](docs/notification-architecture.md) before relevant edits. Preserve the generated Next.js block in [AGENTS.md](AGENTS.md); follow installed Next docs, not assumptions from older versions.

- Canonical local `.env.local` targets real Neon `production`; Cloudflare stage2 uses separate `lgc-bot-test`, while Auth/media stay production services. Domain `legrandecentre.vn` is Vercel. `npm run deploy` updates only stage2; never infer Vercel deployment/DB settings from Wrangler or a build. Migrate verified runtime DB explicitly, never from build/deploy.
- Preserve 15-minute signed admin cookie, two business roles and deliberate-action-only renewal; no passive polling/focus refresh. Preserve server authorization, RLS, property locks, revision CAS, receipts and business audit. Lease recording is metadata-only, not a mandatory PDF/signature workflow; historical private links remain.
- Lead/intake/audit/idempotency **and source outbox** commit together via `public:intake`. Never replace the durable outbox with `after`, fire-and-forget, synchronous Render sending in the form route, or frontend send. Form success means source commit, not Zalo delivery. Duplicate contact receipt must not enqueue twice; no historical backfill.
- Website DB is separate from Render bot DB. Do not pass business DB credentials to bot; use server-only HTTPS endpoint/key. `NOTIFICATIONS_URL` is full `/v1/notifications`; generic SDK `baseUrl` is service origin instead.
- Preserve DB-generated `contact:<intake-id>:zalo` key and payload across retry/lost ACK. Source dispatcher leases/`SKIP LOCKED` and closes transactions before network. Only valid HTTP200/202 `queued`/`sending`/`sent` receipt transfers ownership and clears source payload; keep it for every failure.
- Internal POST dispatch requires dedicated `NOTIFICATION_DISPATCH_SECRET` ≥32 characters before DB access. Never reuse website key/webhook secret, log secrets/PII/provider bodies, or expose env via `NEXT_PUBLIC_*`. Contact notification contains reference/name/phone/intent only, not full notes/email/intake.
- Preserve actual Cloudflare one-minute scheduled wrapper and OpenNext self-binding context. Local Next has no scheduler. Optional `NOTIFICATION_PRODUCTION_DISPATCH_URL` is only enabled after production route/env/DB verification and matching dedicated secret; it supplements stage2 dispatch, does not move DB ownership or deploy Vercel.
- Bot registry owns finite key issue/rotate/revoke/limit; owner-only group `/init` links many groups with SQL-enforced cap/default3 and idempotent repeat. Never add key exchange to groups/public form. Non-owner private bot replies exactly `Liên hệ chủ sở hữu để mở khóa tính năng`, no AI/quota.
- Render durable recipient retries are at-least-once; provider ACK then DB crash can duplicate. Preserve receipt/metadata and payload cleanup; never claim exactly-once/read delivery. Render Free cold-start webhooks are best-effort before inbox commit, not protected by website source outbox.
- Current contact outbox sends Zalo only. Gmail API support in bot still requires real four-variable OAuth configuration and fixed mailbox; no SMTP/App Password or unobserved Gmail-live claim.
- Use forward migrations, owned disposable loopback PostgreSQL for DB tests, repo scripts only when assigned. Preserve unrelated UI work. Record exercised checks/deploy/runtime evidence honestly; local proof is not production acceptance.
